# 1. Введение
[Обзор всего документа SRS.]

## Цели
Формирование требований к системе учета программных лицензий (СУПЛ) на основе стандарта IEEE Std 830-1998 для согласования архитектуры, функциональности и правил приемки программного продукта между разработчиками, тестировщиками и заказчиком.

## Границы применения
Система предназначена для централизованного учета программных и аппаратных лицензий на предприятии со структурой холдинга.

**Функциональные границы:**
* Ведение единого реестра лицензий ПО с привязкой к юридическим лицам холдинга, контрагентам-продавцам и компаниям-правообладателям.
* Фиксация параметров лицензий: название ПО, срок действия (ограниченный или бессрочный), объем (количество копий), форма ключа (программный код или аппаратный USB-носитель).
* Разделение схем лицензирования: привязка к конечному устройству либо конкурентный (сетевой) доступ для пула сотрудников с контролем лимита одновременных сессий.
* Формирование отчетов по текущим активным лицензиям и лицензиям с истекающим сроком действия (с возможностью задания периода предупреждения в 2, 3 и 6 месяцев).
* Сохранение и просмотр просроченных лицензий.
* Уведомления о приближении срока окончания лицензий.

**Вне границ системы:**
* Система не выполняет функции сервера сетевых лицензий (License Manager) и не блокирует запуск сторонних программ на уровне операционной системы.
* Система не ведет бухгалтерские проводки и финансовые расчеты.

## Термины и аббревиатуры

| Обозначение | Определение |
|-------------|-------------|
| **СУПЛ (SAM)** | Система учета программных лицензий (Software Asset Management). |
| **Юрлицо холдинга** | Организация в составе холдинга, на баланс которой оформлена лицензия. |
| **Правообладатель** | Компания-разработчик софта, владеющая авторскими правами (например, ООО "1С"). |
| **Контрагент** | Партнер, дистрибьютор или франчайзи, у которого приобретена лицензия. |
| **Программная лицензия** | Лицензия, активируемая цифровым ключом или кодом активации. |
| **Аппаратная лицензия** | Лицензия, поставляемая на физическом электронном носителе (USB-токен). |
| **Лицензия на устройство** | Модель лицензирования с привязкой к конкретному компьютеру или серверу. |
| **Конкурентная лицензия** | Модель лицензирования, допускающая одновременную работу фиксированного числа пользователей из утвержденного списка. |
| **Срочная лицензия** | Лицензия с установленной датой окончания действия. |
| **Бессрочная лицензия** | Лицензия без даты окончания действия. |
| **Активная лицензия** | Несписанная бессрочная лицензия либо несписанная срочная лицензия, дата окончания которой не раньше текущей даты. |
| **Просроченная лицензия** | Несписанная срочная лицензия, дата окончания которой раньше текущей даты. |
| **Период предупреждения** | Временной интервал (2, 3 или 6 месяцев) для фильтрации истекающих лицензий и формирования уведомлений. |

# 2. Общее описание

## Описание изделия
СУПЛ представляет собой централизованное веб-приложение, предназначенное для работы во внутренней сети предприятия.

- **Интерфейсы системы**: клиент-серверная архитектура: веб-клиент, сервер приложений и реляционная база данных.
- **Интерфейсы пользователя**: доступ через стандартный веб-браузер (Google Chrome, Firefox, Edge, Яндекс.Браузер). Графический интерфейс включает экранные формы карточек лицензий, таблицы реестров с фильтрацией и экран генерации отчетов.
- **Интерфейсы аппаратных средств ЭВМ**: стандартные рабочие места пользователей (монитор, клавиатура, мышь). Взаимодействие с аппаратными USB-ключами ограничивается ручным учетом их реквизитов (серийный номер, ответственное лицо).
- **Интерфейсы программного обеспечения**: взаимодействие с реляционной СУБД (PostgreSQL / MySQL). Возможность выгрузки отчетов в форматы XLSX, CSV и PDF.
- **Интерфейсы коммуникаций**: взаимодействие компонентов системы и доступ к базе данных по локальной сети через стек протоколов TCP/IP.
- **Ограничения памяти**: потребление оперативной памяти клиентским веб-приложением в браузере - не более 250 МБ. Объем дискового пространства сервера под базу данных - от 2 ГБ для учета до 10 000 записей.
- **Действия**: интерактивная работа пользователей и автоматическое ежедневное фоновое задание по проверке сроков действия лицензий и формированию оповещений.

## Функции изделия
1. **Ведение справочников:** учет юридических лиц холдинга, компаний-правообладателей, контрагентов-поставщиков, оборудования и сотрудников.
2. **Учет лицензий:** создание, просмотр, редактирование и списание карточек лицензий со всеми атрибутами (название ПО, юрлицо-владелец, контрагент, правообладатель, признак срочной или бессрочной лицензии, срок окончания для срочной лицензии, число копий, тип ключа, модель лицензирования). Просроченные лицензии сохраняются и доступны для просмотра.
3. **Распределение прав использования:**
   * Назначение лицензий "на устройство" на конкретные рабочие станции.
   * Назначение конкурентных лицензий на утвержденный список сотрудников с фиксацией лимита одновременных рабочих мест.
4. **Формирование отчетов:**
   * Отчет по активным лицензиям на текущую дату.
   * Отчет по лицензиям с истекающим сроком действия с периодом предупреждения в 2, 3 или 6 месяцев.
5. **Уведомления:** оповещение о приближении срока окончания срочных лицензий в выбранный период предупреждения.

## Характеристики пользователей
* **Системный администратор**: настройка системы, управление учетными записями и правами доступа, ведение общесистемных справочников.
* **Специалист по закупкам / SAM-менеджер**: внесение договоров и карточек лицензий, распределение лицензий по пользователям и ПК, контроль сроков окончания и формирование отчетов.
* **Руководитель IT**: просмотр сводной аналитики, мониторинг рисков просрочки и контроль используемого ПО.

## Ограничения
* Доступ к данным и операциям разграничивается на основе ролевой модели доступа (RBAC).
* Серверная часть должна развертываться в среде ОС Linux.
* Персональные данные сотрудников защищаются согласно требованиям информационной безопасности предприятия.

## Предположения и зависимости
* Внесение данных о закупках и изменениях лицензий выполняется ответственными сотрудниками без задержек.
* На сервере настроена синхронизация системного времени по протоколу NTP для корректного расчета сроков истечения лицензий.

# 3. Детальные требования

## Функциональные требования

Операции доступны после входа в систему (ФТ-15) и проверки прав (ФТ-16). В карточке обязательны название ПО, юридическое лицо - владелец лицензии, продавец, правообладатель, количество копий (положительное целое число), тип и реквизиты ключа, модель лицензирования и признак "Срочная" или "Бессрочная". Для программного ключа указывается ключ или код активации, для аппаратного - серийный номер USB-носителя и ответственное лицо. Юридическое лицо, продавец, правообладатель и ответственное лицо выбираются из справочников.
### Учет и просмотр лицензий

#### ФТ-01. Создание срочной лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-01 |
| Название | Создание срочной лицензии |
| Описание | Система должна позволять создавать карточку лицензии с ограниченным сроком действия. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Связанные записи внесены в справочники. |
| Входные данные | Общие обязательные поля карточки, признак "Срочная" и дата окончания действия. |
| Результат | Карточка сохранена с уникальным идентификатором. Если дата окончания раньше текущей даты сервера, лицензия отображается как просроченная; иначе - как активная. |
| Обработка ошибок | При незаполненных обязательных полях, неверной дате или некорректном количестве копий сохранение отклоняется; система указывает поля, требующие исправления. |

#### ФТ-02. Создание бессрочной лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-02 |
| Название | Создание бессрочной лицензии |
| Описание | Система должна позволять создавать карточку лицензии без ограничения срока действия. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Связанные записи внесены в справочники. |
| Входные данные | Общие обязательные поля карточки и признак "Бессрочная". |
| Результат | Карточка сохранена с уникальным идентификатором и без даты окончания. Лицензия считается активной до списания. Поле даты окончания недоступно для заполнения. |
| Обработка ошибок | При незаполненных обязательных полях или некорректном количестве копий сохранение отклоняется; система указывает поля, требующие исправления. |

#### ФТ-03. Просмотр и изменение карточки лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-03 |
| Название | Просмотр и изменение карточки лицензии |
| Описание | Система должна позволять просматривать полные сведения о выбранной лицензии и изменять данные ее карточки в соответствии с правами пользователя. |
| Исполнитель | SAM-менеджер - просмотр и изменение; руководитель IT - только просмотр. |
| Предусловия | Карточка лицензии существует. Изменение допускается только для несписанной карточки. |
| Входные данные | Идентификатор лицензии и выбранная операция: просмотр или изменение. При изменении - новые значения полей карточки. |
| Результат | При просмотре отображаются поля карточки и состояние лицензии. Для модели "На устройство" показываются назначенные устройства, число занятых и свободных копий; для конкурентной - список сотрудников и лимит одновременных рабочих мест. Просроченные и списанные карточки доступны для просмотра. При изменении данные сохраняются с учетом обязательных полей и правил ФТ-01 или ФТ-02; идентификатор карточки сохраняется. При переходе к бессрочной лицензии дата окончания удаляется. |
| Обработка ошибок | Если карточка не найдена, система показывает сообщение "Лицензия не найдена". При изменении отклоняются неверные данные, уменьшение числа копий ниже числа назначенных устройств или установленного конкурентного лимита, а также смена модели лицензирования при наличии назначений. Изменение списанной карточки или изменение руководителем IT отклоняется. Причина отказа отображается, прежние данные сохраняются. |

#### ФТ-04. Списание лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-04 |
| Название | Списание лицензии |
| Описание | Система должна позволять списывать лицензию после подтверждения пользователем. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Карточка лицензии существует и еще не списана. |
| Входные данные | Идентификатор лицензии и подтверждение списания. |
| Результат | Лицензия получает состояние "Списана". Карточка и сведения о назначениях сохраняются для просмотра. Лицензия исключается из отчетов по активным и истекающим лицензиям и недоступна для новых назначений. |
| Обработка ошибок | Если лицензия не найдена или уже списана, система сообщает об этом. При отмене подтверждения состояние не меняется. |

#### ФТ-05. Просмотр реестра лицензий

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-05 |
| Название | Просмотр реестра лицензий |
| Описание | Система должна показывать реестр лицензий с фильтрацией по названию ПО, юридическому лицу и состоянию. |
| Исполнитель | SAM-менеджер, руководитель IT. |
| Предусловия | Пользователь открыл реестр лицензий. |
| Входные данные | Необязательные фильтры; состояние - "Активная", "Просроченная" или "Списана". |
| Результат | Отображаются подходящие записи: идентификатор, название ПО, юридическое лицо, вид срока, дата окончания или отметка "Бессрочная", состояние. Без фильтров доступны все записи, включая просроченные и списанные. |
| Обработка ошибок | При отсутствии подходящих записей система показывает пустой список и сообщение "Лицензии не найдены". |

### Назначение лицензий

#### ФТ-06. Назначение лицензии на устройство и отмена назначения

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-06 |
| Название | Назначение лицензии на устройство и отмена назначения |
| Описание | Система должна позволять назначать одну копию лицензии выбранному устройству и отменять существующее назначение. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Для назначения лицензия должна быть активной и иметь модель "На устройство", а устройство - быть внесено в справочник. Для отмены должно существовать назначение выбранной лицензии на устройство; активность лицензии не требуется. |
| Входные данные | Идентификаторы лицензии и устройства, операция: назначение или отмена назначения. |
| Результат | При назначении связь с устройством сохраняется, число свободных копий уменьшается на одну. Одно устройство занимает одну копию данной лицензии; число назначений не превышает число приобретенных копий. При отмене связь удаляется, число занятых копий уменьшается на одну. Повторное назначение освобожденной копии возможно только для активной лицензии. |
| Обработка ошибок | При назначении отсутствие свободных копий вызывает отказ с сообщением "Нет свободных копий". Несоответствие модели, неактивная лицензия, неизвестное устройство или повторное назначение той же лицензии тому же устройству также вызывают отказ с пояснением. Если отменяемое назначение не найдено, система сообщает об этом и не изменяет число занятых копий. |

#### ФТ-07. Управление списком сотрудников конкурентной лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-07 |
| Название | Управление списком сотрудников конкурентной лицензии |
| Описание | Система должна позволять добавлять сотрудников в список пользователей конкурентной лицензии и исключать их из списка. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Для добавления лицензия должна быть активной, иметь конкурентную модель и установленный лимит, а сотрудник - быть внесен в справочник. Для исключения сотрудник должен находиться в списке выбранной конкурентной лицензии; активность лицензии не требуется. |
| Входные данные | Идентификаторы лицензии и сотрудника, операция: добавление или исключение. |
| Результат | Сотрудник добавлен в список или исключен из него. Остальные назначения и лимит одновременных рабочих мест не изменяются. Число сотрудников в списке может превышать этот лимит. |
| Обработка ошибок | При добавлении повторная запись, неизвестный сотрудник, неактивная лицензия, неверная модель или отсутствие лимита вызывают отказ с поясняющим сообщением. При исключении система отклоняет операцию, если сотрудник отсутствует в списке. Если лицензия не найдена, система сообщает об этом; ранее сохраненные назначения не изменяются. |

#### ФТ-08. Установка лимита конкурентной лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-08 |
| Название | Установка лимита конкурентной лицензии |
| Описание | Система должна позволять задавать и изменять учетный лимит одновременных рабочих мест конкурентной лицензии. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Карточка существует, имеет конкурентную модель и не списана. |
| Входные данные | Идентификатор лицензии и новое значение лимита. |
| Результат | Сохранено положительное целое значение, не превышающее приобретенное количество копий. Список сотрудников не меняется. Лимит хранится как учетный параметр; система не управляет запуском сторонних программ. |
| Обработка ошибок | Нулевое, отрицательное, дробное значение или превышение количества копий отклоняется с пояснением. При неверной модели или списанной лицензии изменение также отклоняется; прежний лимит сохраняется. |

### Отчеты и уведомления

#### ФТ-09. Отчет по активным лицензиям

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-09 |
| Название | Отчет по активным лицензиям |
| Описание | Система должна формировать отчет по лицензиям, активным на текущую дату сервера. |
| Исполнитель | SAM-менеджер, руководитель IT. |
| Предусловия | Пользователь открыл раздел отчетов. |
| Входные данные | Запрос на формирование отчета и необязательный фильтр по юридическому лицу. |
| Результат | Отчет включает несписанные бессрочные лицензии и несписанные срочные лицензии с датой окончания не раньше текущей даты. Отображаются дата формирования, идентификатор, название ПО, юридическое лицо, дата окончания или отметка "Бессрочная", количество копий, тип ключа и модель лицензирования. |
| Обработка ошибок | Если подходящих лицензий нет, формируется пустой отчет с сообщением "Лицензии не найдены". При технической ошибке система сообщает, что отчет не сформирован. |

#### ФТ-10. Отчет по истекающим лицензиям

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-10 |
| Название | Отчет по истекающим лицензиям |
| Описание | Система должна формировать отчет по лицензиям, срок действия которых истекает в выбранный период. |
| Исполнитель | SAM-менеджер, руководитель IT. |
| Предусловия | Пользователь открыл раздел отчетов. |
| Входные данные | Период 2, 3 или 6 месяцев и необязательный фильтр по юридическому лицу. |
| Результат | Отбираются несписанные срочные лицензии с датой окончания от текущей даты сервера до даты через выбранное число календарных месяцев включительно. Если соответствующего числа в конечном месяце нет, используется его последний день. Отчет содержит период, дату формирования, идентификатор, название ПО, юридическое лицо, дату окончания и количество копий; записи упорядочены по дате окончания. |
| Обработка ошибок | Недопустимый период отклоняется с указанием значений 2, 3 и 6 месяцев. При отсутствии записей формируется пустой отчет с сообщением "Лицензии не найдены"; при технической ошибке сообщается о невозможности сформировать отчет. |

#### ФТ-11. Выгрузка отчета

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-11 |
| Название | Выгрузка отчета |
| Описание | Система должна позволять выгружать сформированный отчет в файл. |
| Исполнитель | SAM-менеджер, руководитель IT. |
| Предусловия | Отчет по ФТ-09 или ФТ-10 сформирован и открыт для просмотра. |
| Входные данные | Выбранный отчет и формат XLSX, CSV или PDF. |
| Результат | Пользователю доступен файл выбранного формата с теми же записями и столбцами, что в открытом отчете. Пустой отчет выгружается с заголовками столбцов. |
| Обработка ошибок | При неподдерживаемом формате или ошибке выгрузки система показывает причину отказа; сформированный отчет остается доступен для просмотра. |

#### ФТ-12. Настройка и формирование уведомлений об истечении

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-12 |
| Название | Настройка и формирование уведомлений об истечении |
| Описание | Система должна позволять устанавливать общий период предупреждения и ежедневно формировать уведомления о лицензиях, истекающих в этот период. |
| Исполнитель | SAM-менеджер - настройка периода; система - ежедневная проверка. Получатели уведомлений - SAM-менеджер и руководитель IT. |
| Предусловия | Для настройки открыт раздел уведомлений. Для автоматической проверки наступило время ежедневного запуска; используется сохраненный период предупреждения, а до его изменения - 2 месяца. |
| Входные данные | При настройке - период 2, 3 или 6 месяцев. При проверке - текущая дата сервера, даты окончания лицензий, их состояния и период предупреждения. |
| Результат | Выбранный период сохранен и применяется при следующей ежедневной проверке. Для лицензий, соответствующих правилам отбора ФТ-10, в приложении доступны уведомления с названием ПО, юридическим лицом, датой окончания и ссылкой на карточку. Для бессрочных, списанных и уже просроченных лицензий новые уведомления о приближении срока окончания не создаются. |
| Обработка ошибок | Недопустимый период отклоняется с указанием разрешенных вариантов; прежняя настройка сохраняется. При сбое проверки ранее созданные уведомления сохраняются; система фиксирует ошибку и повторяет проверку при следующем ежедневном запуске. |

|---|---|

| Исполнитель | Системный администратор. |
| Предусловия | Учетная запись пользователя существует. |
| Входные данные | Идентификатор пользователя и одна роль: "Системный администратор", "SAM-менеджер" или "Руководитель IT". |

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-15 |
| Название | Вход в систему |

| Исполнитель | Пользователь системы. |
| Предусловия | Открыта форма входа. |
| Входные данные | Логин и пароль. |
| Результат | При верных учетных данных пользователь входит в систему и получает доступ к функциям своей роли. Если роль не назначена, отображается сообщение о необходимости обратиться к администратору, рабочие функции недоступны. |
| Обработка ошибок | При неверных учетных данных вход отклоняется с сообщением "Неверный логин или пароль". |

#### ФТ-16. Проверка прав доступа

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-16 |
| Название | Проверка прав доступа |
| Описание | Система должна проверять роль пользователя при каждом запросе к рабочим функциям, включая прямой переход по ссылке. |
| Исполнитель | Система при запросе пользователя. |
| Предусловия | Получен запрос на просмотр данных или выполнение операции. |
| Входные данные | Учетная запись пользователя, назначенная роль и запрашиваемая операция. |
| Результат | Администратору доступны управление учетными записями, назначение ролей и ведение справочников. SAM-менеджеру доступны учет и назначение лицензий, просмотр, отчеты, их выгрузка, настройка периода и уведомления. Руководителю IT доступны просмотр лицензий, формирование и выгрузка отчетов и просмотр уведомлений; изменение лицензий, назначений, пользователей и настроек запрещено. |
| Обработка ошибок | Неавторизованный пользователь направляется на форму входа. При отсутствии роли или разрешения запрос отклоняется с сообщением "Недостаточно прав"; данные не изменяются. |
